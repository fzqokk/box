# 店铺宣传小程序 产品需求文档（PRD）

- 文档版本：V1.1（草稿）
- 编写日期：2026-09-17
- 产品名称：etiniabox 店铺宣传小程序（暂定名，以店铺实际名称为准）
- 技术基线：uni-app x 编译微信小程序 + 微信云开发（云数据库 / 云存储 / 云函数）
- 文档状态：待评审
- 修订记录：V1.1 店主端改为微信自带登录，管理端由独立网页后台调整为小程序内置管理端（openid 白名单识别身份）；V1.0 初稿。

## 一、产品概述

### 1.1 产品背景

- 店铺为线下照相服务门店，需要一款轻量线上载体承接到店顾客与潜在顾客。
- 现有宣传物料（桌卡、海报、照片墙等）缺少统一的线上入口，套餐信息与季度活动更新依赖线下物料更换，不及时且成本高。
- 微信小程序扫码即达、无需安装，适合单店低成本宣传运营。

### 1.2 产品定位

- 单店宣传展示型小程序，核心是「展示 + 互动传播」，不承载任何交易。
- 顾客端（微信小程序）：浏览套餐、查看季度活动、扫码打卡、生成分享海报、查看门店信息。
- 店主端（小程序内置管理端）：店主在同一小程序内经微信自带登录识别身份，自主维护套餐、参数与季度活动内容。

### 1.3 产品目标

- 为到店顾客提供扫码打卡互动，增强到店体验与品牌记忆点。
- 通过打卡后生成带店铺二维码的分享海报，激励顾客转发，带来社交裂变曝光。
- 让店主可随时自主更新套餐与季度活动，保证线上信息与店内一致。
- 运营数据依托微信小程序后台自带统计分析（访问人数、页面路径、分享次数等），无需自行埋点采集用户数据。

### 1.4 范围边界（本期明确不做）

- 不接入微信支付，不产生任何交易行为；价格仅作展示用途。
- 不采集任何个人信息：不获取用户头像昵称、不获取手机号、不做注册登录、不留存用户行为数据。
- 不做在线预约、在线选片、客服会话等业务功能。
- 顾客打卡记录仅保存在其手机本地，不上传服务器。

## 二、用户与场景分析

### 2.1 角色定义

- 顾客（C 端）：到店顾客与通过分享进入的潜在顾客，免登录使用全部功能，无身份区分。
- 店主（管理端）：店铺经营者，通过微信自带登录（静默获取 openid）与管理员白名单比对识别身份，拥有全部内容的增删改权限；系统仅此一个管理角色，无账号密码体系。

### 2.2 核心使用场景

- 场景一：扫码进入
  - 顾客扫描店内物料（桌卡、海报、相框摆台）上的小程序码进入小程序首页。
  - 部分物料的小程序码携带场景参数（scene=checkin），扫码后直达打卡页。
- 场景二：到店打卡
  - 顾客在打卡页点击打卡，当天记录一次打卡，形成打卡日历与累计次数。
  - 打卡成功后可一键生成分享海报。
- 场景三：分享传播
  - 顾客将海报保存到相册发朋友圈，或把小程序卡片转发给好友/群聊。
  - 新用户扫描海报上的店铺二维码进入小程序，形成传播闭环。
- 场景四：浏览套餐
  - 顾客在套餐列表查看全部上架套餐，进入详情查看拍摄参数（拍摄时长、服装造型、精修张数、出片规格等）与展示价格。
- 场景五：查看季度活动
  - 顾客在首页轮播看到当季海报，点击进入活动详情页了解活动主题与说明。
- 场景六：店主管理
  - 店主打开同一小程序，系统经微信登录自动识别其管理员身份并展示管理入口，即可更换套餐内容与参数、上下架套餐、更换季度海报、维护门店信息。

### 2.3 用户价值小结

- 顾客：快速了解店内有什么拍、多少钱、当季有什么活动；打卡留念并可分享。
- 店主：一次配置线上展示位，随时自主更新；借顾客分享获得低成本曝光。

## 三、产品结构

### 3.1 信息架构

- 顾客端小程序（TabBar 四个页签：首页 / 套餐 / 打卡 / 门店）
  - 首页：店铺头图与一句话简介、当季活动轮播、推荐套餐卡片、打卡入口。
  - 套餐：套餐列表 → 套餐详情页。
  - 打卡：打卡日历与累计次数 → 分享海报生成弹层。
  - 门店：门店介绍、环境相册、营业时间、地址导航、联系电话。
  - 独立页面：季度活动详情页（由首页轮播或活动卡片进入）。
- 店主端管理功能（内置在同一小程序内，无独立网页后台）
  - 身份识别：微信自带登录静默完成，无登录页；管理入口仅对白名单 openid 用户可见（入口位于「门店」页顶部）。
  - 套餐管理：列表、新建、编辑、上下架、排序、删除。
  - 活动管理：季度活动与海报维护。
  - 门店信息维护。

### 3.2 页面清单

- pages/index/index —— 首页（TabBar）
- pages/package/list —— 套餐列表（TabBar）
- pages/package/detail —— 套餐详情
- pages/checkin/checkin —— 打卡（TabBar）
- pages/about/about —— 门店信息（TabBar）
- pages/campaign/detail —— 季度活动详情（非 TabBar，带参进入）
- 分享海报：打卡页内的弹层组件（canvas 绘制），不设独立页面
- 管理端页面（同小程序内）：pages/admin/index —— 管理首页（入口与内容概览）、pages/admin/package-edit —— 套餐新建/编辑、pages/admin/campaign-edit —— 活动新建/编辑、pages/admin/store-info —— 门店信息编辑；套餐与活动的列表管理操作复用前台列表页，追加「编辑 / 上下架 / 删除」入口（仅白名单用户可见）

## 四、功能需求详述

### 4.1 顾客端功能

#### 4.1.1 首页

- 功能描述：店铺线上门面，聚合活动、推荐套餐与打卡入口。
- 展示内容：
  - 店铺名称、头图、一句话简介。
  - 当季活动轮播（可配置多图，自动播放）。
  - 推荐套餐卡片（封面、名称、展示价格），展示 2-4 个。
  - 打卡入口按钮。
- 交互规则：
  - 点击轮播图进入对应活动详情页。
  - 点击套餐卡片进入套餐详情页。
  - 点击打卡按钮进入打卡 Tab。
- 业务规则：
  - 轮播仅展示「上架且在有效期内」的活动，按 sort 排序；过期活动自动隐藏。
  - 推荐套餐取「上架且标记推荐」的套餐，按 sort 取前 4 个；不足则按实际数量展示。
- 空态处理：无活动时轮播区域隐藏；无推荐套餐时展示引导文案「套餐整理中，敬请期待」。

#### 4.1.2 套餐列表页

- 功能描述：展示全部上架套餐。
- 展示内容：封面图、套餐名称、一句话简介、展示价格。
- 排序规则：按后台配置的 sort 值升序，同值按更新时间倒序。
- 空态处理：显示「套餐整理中，敬请期待」占位。

#### 4.1.3 套餐详情页

- 功能描述：呈现单个套餐的完整信息与拍摄参数。
- 展示内容：
  - 详情图组（多图，可滑动）。
  - 套餐名称、简介、展示价格。
  - 参数明细：以「参数名 — 参数值」列表呈现，例如「拍摄时长 — 60 分钟」「服装造型 — 2 套」「精修 — 15 张」「底片 — 全送」。
  - 适用说明 / 温馨提示（可选文本）。
- 交互规则：支持转发好友，转发卡片标题带套餐名、封面带封面图。
- 业务规则：
  - 价格仅为展示文本（如「￥299 起」），页面不得出现任何支付、下单、预约按钮或引导词汇。
  - 已下架套餐若被直接访问，展示「该套餐已下架」提示页。

#### 4.1.4 季度活动详情页

- 功能描述：展示单个季度活动的完整信息。
- 展示内容：活动海报大图、活动主题、活动说明（图文）、有效期（起止日期）、参与方式（文本说明，如「到店出示本页即可」）。
- 业务规则：
  - 仅「上架」状态活动可访问；已过期活动可访问但显著标注「活动已结束」。
  - 页面内不出现任何支付、下单引导。

#### 4.1.5 扫码打卡

- 功能描述：顾客到店后点击打卡，形成本机打卡记录，是扫码场景的核心互动。
- 展示内容：当月打卡日历视图（已打卡日期高亮）、累计打卡次数、今日打卡状态按钮。
- 交互规则：
  - 点击「打卡」按钮完成当日打卡，按钮态变为「今日已打卡」。
  - 打卡成功后弹出分享海报生成入口。
  - 支持切换查看历史月份。
- 业务规则：
  - 每自然日仅可打卡一次，以本机记录的日期判断。
  - 打卡记录（打卡日期数组）仅存于本机 storage，不上传、不关联账号。
  - 更换设备、删除小程序后记录不保留，属预期行为，页面文案需说明「打卡记录保存在本机」。
- 扫码直达：小程序码携带 scene=checkin 时，冷启动/热启动均跳转至打卡页。

#### 4.1.6 分享海报

- 功能描述：生成本店宣传分享图，供顾客保存转发，是打卡玩法与传播的关键闭环。
- 海报内容：店铺名称、店铺 LOGO、店铺小程序码、打卡文案（如「我在 etiniabox 完成第 N 次打卡」）、当季活动主题元素（有活动时可选）。
- 交互规则：
  - 打卡页「生成分享海报」按钮触发。
  - canvas 在本机合成图片 → 弹层预览 → 「保存到相册」。
  - 保存相册需用户授权相册写入权限（用户主动触发时申请）。
- 业务规则：
  - 海报仅包含店铺信息与打卡文案，不包含用户照片与任何个人信息；合成全程在本机完成，不经过服务器。
  - 海报上的小程序码为固定店铺码（不带个人参数）。
- 异常处理：相册授权被拒时，展示引导文案并提供跳转设置页开启授权的入口。

#### 4.1.7 门店信息页

- 功能描述：展示店铺整体宣传信息。
- 展示内容：门店名称、LOGO、店铺介绍、店内环境相册、营业时间、门店地址、联系电话（展示用）。
- 交互规则：
  - 点击地址：拉起微信内置地图查看位置并提供导航（仅展示店铺位置，不获取用户位置）。
  - 点击电话：用户主动点击后拉起拨号盘。
- 业务规则：不自动调用定位授权；电话仅展示，不做外呼记录。

### 4.2 店主端管理功能

#### 4.2.1 微信登录与管理员识别

- 店主端登录使用微信自带登录能力：wx.login 静默完成，无弹窗授权、无账号密码、无登录页。
- 云函数换取 openid 后与管理员白名单比对：命中白名单则展示管理入口并放行写操作；未命中则全程不显示任何管理入口，写接口一律拒绝。
- 管理入口位于「门店」页顶部（仅白名单用户可见），进入管理首页；管理员白名单由开发在云函数配置中维护（新增/移除店主），不在界面中暴露。
- 仅一个管理员角色（店主），无角色权限体系。

#### 4.2.2 套餐管理

- 列表页：展示全部套餐（含已下架），显示名称、价格、状态、排序值、更新时间；支持按名称搜索。
- 新建 / 编辑字段：
  - 套餐名称（必填，≤ 30 字）。
  - 封面图（必填，单图）。
  - 一句话简介（≤ 40 字）。
  - 展示价格（文本，如「￥299 起」，不做数值校验，因不涉及交易）。
  - 参数明细：可增删多行「参数名 / 参数值」，参数名 ≤ 12 字、参数值 ≤ 30 字，至少 1 行，可拖拽排序。
  - 详情图（多图上传，可拖拽排序）。
  - 是否首页推荐（开关）。
  - 排序值（数字，越小越靠前）。
- 上下架：开关切换，下架后小程序端立即不可见（重新进入页面后生效）。
- 删除：二次确认弹窗；采用软删除（标记 deleted），不物理清除。
- 图片上传：前端自动压缩（封面长边 ≤ 800px、详情图长边 ≤ 1080px），上传至云存储。

#### 4.2.3 活动管理（季度海报）

- 列表页：展示全部活动，显示主题、季度、有效期、状态。
- 新建 / 编辑字段：活动主题（必填 ≤ 30 字）、季度标识（如 2026-Q3，选择器）、海报图（必填）、活动说明（图文编辑，支持段落与图片）、有效期起止日期、排序值、上下架开关。
- 业务规则：允许多个活动同时上架；小程序端仅展示「上架且当前日期在有效期内」的活动。

#### 4.2.4 门店信息维护

- 编辑字段：门店名称、LOGO、店铺介绍、环境相册（多图）、营业时间、门店地址（文本）、地图坐标（地图选点）、联系电话。
- 信息为全局单条记录，保存即生效。

## 五、数据需求

### 5.1 云数据库集合

- 集合 packages（套餐）：
  - _id：文档 ID。
  - name：套餐名称。
  - cover_image：封面图 fileID。
  - summary：一句话简介。
  - price_display：展示价格（文本）。
  - params：参数数组，每项含 param_name（参数名）、param_value（参数值）。
  - detail_images：详情图 fileID 数组（有序）。
  - is_featured：是否首页推荐（布尔）。
  - sort：排序值（数字）。
  - status：upper（上架）/ lower（下架）。
  - deleted：软删除标记（布尔）。
  - created_at / updated_at：时间戳。
- 集合 campaigns（季度活动）：
  - _id、title（主题）、season（季度标识）、banner_image（海报图 fileID）、description（图文说明，结构化块数组）、start_date、end_date、sort、status、deleted、created_at、updated_at。
- 集合 store_info（门店信息，单条文档）：
  - store_name、logo、intro、photos（环境相册 fileID 数组）、business_hours、address、longitude、latitude、contact_phone、updated_at。
- 管理员白名单：不设账号密码表；白名单 openid 列表维护于云函数配置（或配置集合 admin_config：openids 数组、updated_at），仅用于店主身份识别。

### 5.2 本机数据（顾客手机 storage）

- checkin_records：dates（已打卡日期数组，格式 YYYY-MM-DD）；累计次数由数组长度派生，不单独存储。
- 相册授权状态等运行时标记。

### 5.3 静态资源

- 全部图片存云存储并通过 CDN 分发，小程序端使用临时链接加载。
- 海报模板底图与店铺小程序码图片由开发预置上传。

## 六、非功能需求

### 6.1 性能

- 首屏可交互时间 ≤ 2 秒（Wi-Fi / 常规 4G 环境）。
- 图片全部懒加载；套餐与活动数量级小（各 ≤ 50 条），列表一次性加载即可，不做分页。
- 海报 canvas 合成时间 ≤ 3 秒。

### 6.2 兼容性

- 微信基础库最低版本 2.30.0，低于版本时提示更新微信。
- 覆盖 iOS 与 Android 主流机型；深色模式不做强制适配（跟随默认）。

### 6.3 安全

- 管理端所有写操作经云函数校验调用方 openid 是否命中管理员白名单，数据库权限规则收紧为「仅云函数可写」。
- 管理端与顾客端共用同一小程序发布，管理入口与写接口对非白名单用户完全不可见 / 不可用。
- 店主上传的图片与文本内容接入微信内容安全检测（security.imgSecCheck / security.msgSecCheck 对应异步接口），检测结果异常的内容禁止上架。
- 顾客端仅开放只读查询：packages 与 campaigns 仅可读 status=upper 且 deleted=false 的记录，store_info 仅可读；本机打卡记录不上传，服务端无任何用户数据表。

### 6.4 可用性

- 断网或加载失败时展示友好错误提示与「重新加载」按钮。
- 全部核心页面（首页、套餐列表/详情、活动详情）支持被分享。
- 分享卡片统一使用店铺 LOGO 或对应内容封面，文案规范由开发按本文档配置。

## 七、合规与审核说明

### 7.1 微信类目建议

- 建议类目：生活服务 — 摄影扩印。
- 提审时按平台要求准备营业执照等资质材料，以提审时平台最新要求为准。

### 7.2 支付合规

- 全程不接入微信支付、不展示任何交易按钮。
- 文案规范：仅使用「价格」「到店咨询」，禁用「立即购买」「下单」「支付」等词汇，避免审核被驳回。

### 7.3 个人信息保护

- 顾客端不调用 getUserProfile、chooseAddress、getPhoneNumber 等涉及个人信息的接口，无授权弹窗、不做注册登录。
- 仅店主管理侧使用微信自带登录（wx.login 静默调用）获取 openid，用于管理员白名单身份识别；openid 为匿名标识，不指向真实身份，需在《用户隐私保护指引》中声明该收集行为与用途。
- 顾客不采集、不上传、不留存任何用户行为数据；打卡记录仅存本机。
- 在微信公众平台配置《用户隐私保护指引》；仅在使用「保存海报到相册」功能时由用户主动触发相册写入授权。
- 分享海报不含用户照片与个人信息。

### 7.4 内容合规

- 套餐图片、海报素材由店主上传，须为自有版权或已获授权素材，PRD 层面向店主明确告知。
- 客片展示类内容本期不做，如后续版本增加，须另做肖像权授权管理（列入 V2.0 评估）。

## 九、验收要点（关键场景）

- 扫码进入：普通店铺码进入首页；携带 scene=checkin 的码直达打卡页。
- 打卡：同一自然日重复点击打卡被限制为一次；杀掉小程序重进后打卡记录仍在（本机）；更换设备后记录清零且页面有相应说明。
- 海报：生成的海报图片完整、清晰，含店铺小程序码，扫码后可正确进入小程序；拒绝相册授权后有引导路径。
- 套餐：后台下架某套餐后，小程序端重新进入不再展示；软删除的套餐不出现。
- 活动：超过有效期的活动自动从首页轮播消失，详情页显示「活动已结束」。
- 合规：全流程不出现支付元素与个人信息授权弹窗（保存海报的相册授权除外）；「价格」文案无交易引导词。
- 管理端：白名单店主经微信登录后可见管理入口并能正常保存内容；非白名单用户全程无管理入口，直接调用写接口被云函数拒绝。
